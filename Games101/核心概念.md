## 一、光栅化

把三维空间的几何形体显示在屏幕上。

---

## 二、叉积判断法（Edge Function）

**用途：** 判断一个点是否在三角形内部。

**思路：** 给定逆时针顺序的三角形顶点 `A → B → C`，对任意点 P，依次计算三条边的**有符号距离**：

```
edge(P, A, B) = (P.x - A.x) * (B.y - A.y) - (P.y - A.y) * (B.x - A.x)
edge(P, B, C) = (P.x - B.x) * (C.y - B.y) - (P.y - B.y) * (C.x - B.x)
edge(P, C, A) = (P.x - C.x) * (A.y - C.y) - (P.y - C.y) * (A.x - C.x)
```

**为什么叉积能判断内外？**

每条边的 `edge(P, A, B)` 计算的是向量 `AP` 和向量 `AB` 的**二维叉积的 z 分量**：

```
AP × AB = |AP||AB|sinθ
```

- 如果 P 在 AB 的左侧（数学坐标系中三角形内部侧），叉积结果 > 0
- 如果 P 在 AB 的右侧，叉积结果 < 0
- 如果 P 恰好在 AB 上，叉积结果 = 0

一个点在三角形内，当且仅当它在**三条边的同一侧**（逆时针顶点时为左侧）。所以：

> 在数学坐标系（y 向上）中，三个 edge 值都 **>= 0** → P 在三角形内；
> 任意一个 **< 0** → P 在三角形外。

**⚠️ 屏幕坐标注意：** 屏幕坐标 y 轴向下，叉积的左右侧与数学坐标相反。所以屏幕坐标下，逆时针三角形内部像素的 edge 值全部 **≤ 0**。实际编码时用 `<=` 判断。

## 三、重心坐标

**用途：** 用一个点离三个顶点的"远近"，来插值该点处任意属性（深度、颜色、法线、UV 等）。

### 直觉理解

重心坐标 `(α, β, γ)` 是三个**权重**，表示点 P 离三个顶点有多"近"：

- 权重越大 → 越靠近对应的顶点
- P 是 A、B、C 的加权平均：**P = α·A + β·B + γ·C**
- 三个权重之和为 1：**α + β + γ = 1**

极端情况：
- 如果 P = A，则 `(α, β, γ) = (1, 0, 0)`
- 如果 P 在边 BC 上，则 `α = 0`

### 怎么算？用面积比

把 P 和三个顶点分别连线，三角形被分成三个子三角形：

```
         A
        /|\
       / | \
      /  |  \
     /   |   \
    B----P----C
```

- **α** = 子三角形(P,B,C) 的面积 ÷ 整个三角形(A,B,C) 的面积 — P **对面**的那个
- **β** = 子三角形(P,C,A) 的面积 ÷ 整个三角形面积
- **γ** = 子三角形(P,A,B) 的面积 ÷ 整个三角形面积

因为 `edge(P, B, C)` 的值正好等于 `2 × 子三角形(P,B,C) 的有符号面积`，所以可以用之前算的 edge 值直接算：

```
alpha = edge(P, B, C) / edge(A, B, C)
beta  = edge(P, C, A) / edge(A, B, C)
gamma = edge(P, A, B) / edge(A, B, C)
```

三个子三角形面积之和等于原三角形面积，所以 `α + β + γ = 1` 恒成立。

### 用重心坐标插值

有了重心坐标，可以对任意顶点属性做**线性插值**：

```
value = α × val_A + β × val_B + γ × val_C
```

可插值的属性包括：

| 属性 | 用途 |
|------|------|
| 深度 z | Z-Buffer 深度测试 |
| 颜色 | Gouraud 着色（平滑颜色过渡） |
| UV 坐标 | 纹理映射 |
| 法线 | Phong 着色（逐像素光照） |

## 四、UV 坐标

**UV 坐标**是人为指定"纹理上的哪个位置对应三角形的哪个顶点"，属于顶点属性。

每个顶点附带一个 `(u, v)`，范围 [0, 1]：
- (0,0) = 纹理左上角， (1,0) = 纹理右上角
- (0,1) = 纹理左下角， (1,1) = 纹理右下角

三角形内部每个像素的 UV 通过重心坐标插值得到，再从纹理中采样颜色。

> UV 不是从包围盒算出来的。包围盒只知道三角形"投影到了屏幕上的哪个区域"，但不知道纹理内容怎么对应到三角形上。UV 的存在就是为了人为指定这个对应关系。

---

## 五、包围盒优化

**包围盒（Bounding Box）：** 三角形在屏幕上的最小矩形区域——取三个顶点 x 的最小/最大值、y 的最小/最大值。

只遍历包围盒内的像素，而不是整张图片（512×512=262,144 像素→几百到几千像素），大幅减少无用计算。

---

## 六、法线（Normal）

**法线**是垂直于表面的单位向量，表示表面在某个点的"朝向"。例如桌面朝上、墙面朝前。

法线是光照计算的基础——它决定了表面能接收到多少光线（漫反射）以及高光的位置。

---

## 七、Blinn-Phong 着色模型

**用途：** 计算一个像素在光照下最终应该显示什么颜色。

### 三个组成部分

Blinn-Phong 把光照拆成三个独立的部分，加起来就是最终颜色：

```
final_color = ambient + diffuse + specular
```

#### ① 环境光（Ambient）

模拟场景中来自四面八方的微弱光线，即使背光面也不是全黑。

```
ambient = ka × kd
```

- `ka`：环境光强度系数（如 0.1 表示取 10% 的物体颜色作为环境底色）
- `kd`：物体本身的漫反射颜色（即用 0-1 表示的 [R, G, B]）

#### ② 漫反射（Diffuse）

光线照到粗糙表面后均匀向四周反射。**表面越正对光源就越亮**，侧面则暗。

```
diffuse = kd × light_intensity × max(0, n·l)
```

- `n`：表面在该像素处的**法线**（单位向量）
- `l`：从表面指向光源的方向（单位向量）
- `n·l`：法线和光源方向的**点积**。越接近 1 说明越正对光源，接近 0 说明在侧面
- `max(0, ...)`：背对光源时结果为 0，不受光
- `light_intensity`：光源强度，越大越亮

#### ③ 高光（Specular）

模拟光滑表面的镜面反射，产生"高光点"。只有当视线方向接近反射方向时才能看到。

```
specular = ks × light_intensity × (n·h)^p
```

- `v`：从表面指向**视线**的方向（单位向量）
- `h`：**半程向量** = 光源方向和视线方向的中间方向
  - `h = normalize(l + v)`
  - Blinn-Phong 用半程向量代替了原始 Phong 模型中的反射光方向计算，效果相似但更简单
- `n·h`：法线与半程向量的点积，值越大说明视线越接近反射方向
- `p`：**高光指数**，控制高光点的大小
  - `p` 越大 → 高光点越小越亮（光滑表面，如金属、镜子）
  - `p` 越小 → 高光点越大越淡（粗糙表面，如塑料、木头）
- `ks`：高光颜色系数（通常为白色 `[1, 1, 1]`）

### 完整代码示例

```python
# 假设已有：法线 n_world，像素世界坐标 P，物体颜色 color
kd = [c / 255.0 for c in color]          # 漫反射色（0-255 → 0-1）

# 环境光
ambient = [ka[i] * kd[i] for i in range(3)]

# 漫反射
l_dir = normalize(light_pos - P)          # 表面 → 光源方向
ndotl = dot(n_world, l_dir)
diffuse = [0, 0, 0]
if ndotl > 0:
    diffuse = [kd[i] * light_intensity * ndotl for i in range(3)]

# 高光（Blinn-Phong）
v_dir = normalize(camera_pos - P)         # 表面 → 视线方向
h_vec = normalize(l_dir + v_dir)          # 半程向量
ndoth = dot(n_world, h_vec)
specular = [0, 0, 0]
if ndoth > 0:
    spec = ndoth ** p
    specular = [ks[i] * light_intensity * spec for i in range(3)]

# 合并
final_color = [ambient[i] + diffuse[i] + specular[i] for i in range(3)]
```

## 八、齐次坐标（Homogeneous Coordinates）

平移变换无法用 3×3 矩阵表达为**线性变换**，所以把三维向量 `(x, y, z)` 扩展到四维 `(x, y, z, w)`，用 4×4 矩阵统一处理平移、旋转、缩放。

```
3D 点     → (x, y, z, 1.0)
3D 向量   → (x, y, z, 0.0)    （w=0 表示方向，平移时不受影响）
齐次 → 3D：(x, y, z, w) → (x/w, y/w, z/w)     （透视除法）
```

---

## 九、MVP 变换

MVP 是把三维模型显示到屏幕上的三个矩阵变换步骤：

```
Model → View → Projection → Viewport
```

**Model 矩阵：** 物体从自身坐标系 → 世界坐标系（平移/旋转/缩放）。

**View 矩阵：** 世界坐标系 → 以摄像机为原点的坐标系。

**Projection 矩阵：** 视锥体映射到 NDC 立方体 `[-1, 1]³`，产生近大远小效果。

**NDC（Normalized Device Coordinates，归一化设备坐标）** 是透视投影后的坐标：
- 范围：`x ∈ [-1, 1]`、`y ∈ [-1, 1]`、`z ∈ [-1, 1]`
- `(-1, -1)` 对应屏幕左下角，`(1, 1)` 对应屏幕右上角
- 与屏幕尺寸无关（512×512 还是 1920×1080，NDC 都是 [-1, 1]）
- 视口变换把 NDC 映射到实际像素坐标

之所以有 NDC 这一步，是为了把不同分辨率、不同宽高比的屏幕统一到一个标准坐标系里——渲染器只需要输出 NDC，最终显示交给视口变换。

**变换顺序：** `clip_pos = Projection × View × Model × vertex`（右乘）

**视口变换：** NDC → 屏幕坐标
```
screen_x = (ndc_x + 1.0) * 0.5 * WIDTH
screen_y = (1.0 - ndc_y) * 0.5 * HEIGHT
```

## 十、深度测试（Depth Test）

**用途：** 解决遮挡问题——当同一像素上有多个物体时，决定显示哪一个。好比三个物体前后排列，都"穿过"同一个像素点，屏幕上这个像素只能显示最前面的那个。

### 光栅化中的深度测试（Z-Buffer）

光栅化是"逐三角形"绘制的，绘制顺序不定，因此需要一个**显式的深度缓冲**：

- framebuffer 旁再开一块 `depth_buffer`，每个像素存"目前画过的最近深度"
- 画新三角形时：新像素的深度 < 已存深度 → 覆盖并更新；否则丢弃

### 光线追踪中的深度测试

逐像素发射光线后，光线会依次穿过多个物体，产生多个交点 `t₁, t₂, t₃, ...`：

```
光线 → 碰到球(近) → 碰到三角形(中) → 碰到球(远)
        t₁ = 2         t₂ = 5          t₃ = 8
```

深度测试在这里就是一句话：**取最小的正 t**，那个点才是眼睛真正看到的表面。光线追踪**不需要 Z-Buffer**——深度测试被内置到"找最近交点"的过程中了。

> 对比：光栅化是"把每个三角形挨个画上去、边画边比深度"，所以深度测试是显式的；光线追踪天然就是"一条光线找到最近交点"，所以深度测试是隐式的。

### Overdraw（过度绘制）

深度比较本身是 O(1) 的廉价操作（一次浮点比较 + 条件写入）。即使同一像素被多个三角形经过，时间也只随重叠次数**线性增长**，不会失控。

真正昂贵的开销在于：如果先算完像素着色（光照）再做深度测试，被遮挡像素的着色计算就**全部白费**了。这种"同一个像素被多个三角形覆盖、大部分是无效劳动"的现象叫 **Overdraw（过度绘制）**。

### 常见优化手段

| 手段 | 说明 |
|------|------|
| **Early-Z** | 把深度测试提前到像素着色之前，通过测试才计算光照，被遮挡像素直接跳过着色 |
| **包围盒** | 只处理三角形在屏幕上的矩形范围，跳过无关像素 |
| **背面剔除** | 背向相机的面直接不绘制 |
| **绘制排序** | 先画远的再画近的，让 Early-Z 更快淘汰无效像素 |

## 十一、克莱姆法则（Cramer's Rule）

**用途：** 解线性方程组 `Ax = b`（方程个数 = 未知数个数）。不需要求逆矩阵，每个未知数用**行列式之比**直接得到。

### 核心公式

```
xᵢ = det(Aᵢ) / det(A)
```

- `A`：系数矩阵
- `Aᵢ`：把 A 的第 i 列替换成右侧向量 b 后的矩阵
- `det`：行列式

### 与 MT 算法的联系

MT 算法求解的方程组 `[-D, E1, E2] · [t, u, v]ᵀ = S` 正是克莱姆法则的直接应用。三个行列式都用**混合积**（标量三重积）高效计算：

```
混合积：(a×b)·c = det([a, b, c])   — 三个列向量构成矩阵的行列式
```

把 MT 中的叉积展开：

```
det  = (D×E2)·E1 = S1·E1        ← 分母行列式
t    = (S2·E2) / det            ← 替换第 1 列（-D → S）
u    = (S1·S)  / det            ← 替换第 2 列（E1 → S）
v    = (S2·D)  / det            ← 替换第 3 列（E2 → S）
```

### 直觉与边界条件

- 行列式的比值本质上衡量"未知数方向上的空间拉伸比例"
- **分母行列式为 0** 说明方程组无唯一解——对应 MT 中"光线与三角形平行"（`S1·E1 ≈ 0`），代码里用 `fabs(det) < 1e-8` 提前返回

## 十二、光线与球体求交

**用途：** 求光线与球面的交点。球体是隐式曲面中最简单的对象，其求交（代入二次方程解判别式）是掌握"光线与物体求交"模式最基础的学习案例。

**详细步骤见：** [`./2-1_ray_sphere/README.md`](./2-1_ray_sphere/README.md)

### 实际应用场景

球体求交在真实引擎中大量使用，只是角色从"渲染主体"变成了"辅助结构"：

| 场景 | 说明 |
|------|------|
| **包围球（Bounding Sphere）** | 碰撞检测、BVH 等加速结构的第一道粗筛——先用廉价的球体求交判断"是否可能命中"，通过才进入精细的三角形求交 |
| **隐式曲面对象** | 粒子系统、元球（Metaballs）等以数学曲面形式存在的对象 |
| **光源与探针** | 球形光源的照射范围判断、环境探针的采样 |
| **教学范例** | 用最简单的解析解掌握"发射光线 → 求交 → 着色"完整流程，为三角形等通用图元打基础 |

### 核心公式

球面方程 `|P - C|² = r²`，代入光线 `P = O + t*D` 展开为二次方程 `at² + bt + c = 0`，用判别式判断是否有根，取最小正 t 即最近交点。

> 说明：实际渲染几何体以三角形网格为主（OBJ 模型全是三角面），球体求交主要用于加速结构和特殊对象。

## 十三、BVH 包围体层次（Bounding Volume Hierarchy）

**用途：** 加速光线与大量图元（三角形/球体等）的求交，把朴素遍历的 O(N) 降到期望 O(log N)。真实引擎里一个模型由成千上万三角形组成，BVH 正是为此设计。

### 不关心图元形状：只用两个通用属性

BVH 构建完全不关心图元是三角形还是球体，只用每个图元的两个通用属性：

| 属性 | 用途 | 三角形 | 球体 |
|------|------|--------|------|
| 包围盒 | 剔除 | 三顶点取 min/max | 球心 ± 半径 |
| 中心点 | 排序键 | 三顶点平均（质心） | 球心 |

所以三角形、球体、任意图元在 BVH 眼中没有区别——这就是为什么一个网格球（576 个三角形）和 64 个球场景的构建机制完全相同。

### 覆盖 vs 存储

- **覆盖**：根节点包围盒 = 所有图元包围盒的并集，它覆盖全部图元——这是正确性前提（打不中根盒必无交点）
- **存储**：图元只被**叶子节点**持有（叶子节点通过索引区间引用图元），根节点和所有内部节点都不存图元（`n_prims = 0`）

一句话：所有图元都在根节点的「覆盖范围」内，但只有叶子节点真正「持有」它们。

### 与二分查找的对比（相似但不相同）

复杂度都是 O(log N)、都靠对半切，但剪枝依据和结果不同：

| | 二分查找 | BVH |
|---|---------|-----|
| 剪枝依据 | 数值**全序**比较（target 与 mid） | **包围盒命中测试** |
| 能否确定方向 | ✅ 比较一次确定在左还是右 | ❌ 左右都要测 |
| 下降路径 | 单一路径，命中即停 | 可能两条路都走，保留候选取最近 |
| 复杂度 | 严格 O(log N) | **期望** O(log N)（光线不一定躲得过盒子） |

### 为什么是二叉树（对比空间划分树）

BVH 切的是**图元集合**（排序后中位数一分为二），不是**空间区域**：

| 树 | 划分对象 | 子节点数 | 特点 |
|----|---------|---------|------|
| BVH（本实现） | 图元集合 | 2 | 平衡、无空节点、包围盒可重叠 |
| KD-Tree | 空间（每层沿一轴切平面） | 2 | 二叉但切空间，盒子不重叠 |
| 四叉树 / 八叉树 | 空间（3D 切 8 块） | 4 / 8 | 易空、易失衡、跨边界图元要特殊处理 |

"按四象限切"是空间划分思路（四叉树/八叉树），BVH 没有这个概念——集合二分只有"两半"这一种自然切法。工程上的 4 叉/8 叉 wide BVH 也只是"把图元集合分成 4/8 组"，本质仍按物体划分（GPU SIMD 并行测盒用）。

### 左右子树怎么分

每个节点三步：选轴 → 排序 → 中位数劈开。

1. **选轴**：计算当前节点图元中心在 X/Y/Z 三个方向的跨度，选跨度最大者。每个节点**独立重选**、三轴交替使用——图元在哪个方向"摊得最开"就沿哪个方向切，左右重叠最少、剔除效率最高
2. **排序**：按图元中心在选定轴上的坐标升序排序
3. **中位数劈开**：排在中位数之前的进左子树，之后的进右子树

**左右是相对比较**，不是绝对规则（如"x < 固定值 → 左"）：中位数每层各自计算，同一个图元在不同层级被反复比较（第 1 层按 X、第 2 层按 Y、第 3 层按 Z），最终落点由「每层节点选轴 + 中心坐标 + 当组中位数」共同决定。

### 索引数组 idx：排序不动图元本体

BVH 用两个数组配合：`prims`（图元本体，顺序 = 生成顺序，永不动）+ `idx`（索引数组，元素是图元在 prims 中的下标）。排序、切分、分组全部发生在 `idx` 上，避免反复拷贝大对象。叶子节点通过 `first_prim ~ first_prim+n_prims` 指向 idx 区间，遍历时用 `prims[idx[i]]` 取真正的图元。
