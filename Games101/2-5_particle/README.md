# 2-5 粒子系统（Particle System）

**文件位置：** `2-5_particle/`

**目标：** 在 2-1 ~ 2-4 的软光栅化/光线追踪基础上，从零实现一个 **CPU 粒子系统**——理解"特效粒子"的本质，为将来理解 UE Niagara 打下基础。

## 为什么做这个（与 UE Niagara 的关联）

Niagara 的粒子系统看起来很玄，但拆开只有三层：

```
① 粒子数据（位置/速度/颜色/大小/寿命）
② 更新规则（每帧怎么改这些数据：重力、衰减、生死）
③ 渲染方式（把粒子画成什么：点、方块、圆、广告牌）
```

**本阶段全部用 CPU + 软渲染实现同样的三层。** 每完成一步，你都会在 README 里看到"这一步对应 Niagara 里的哪个概念"——将来学 Niagara 时，你已经有完整的心智模型。

> 参考 GAMES101 1-1 ~ 1-7（Python 软光栅化）与 2-1 ~ 2-4（C++ 光线追踪）的代码组织：**Vec3 / framebuffer / PPM 输出沿用既有写法**。本阶段全部用 C++，不需要 Eigen（不涉及矩阵运算）。

## 开发环境

- C++17 + CMake（与 2-1 ~ 2-4 相同）
- 输出：PPM 图片（单帧）与 PPM 序列（多帧动画）
- 构建命令（在 `2-5_particle/` 目录下）：
  ```cmd
  cmake -B build                                    # 配置 CMake，在 build/ 目录生成构建文件
  cmake --build build --config Release              # 编译项目，生成 Release 版可执行文件
  .\build\Release\ray_particle.exe                  # 运行程序，输出 PPM 序列
  ```
  - **用途：** 配置并编译粒子系统项目，生成可执行文件
  - **预期产出：** `ray_particle.exe`（在 `build/Release/` 目录下）
  - **参数传递：** 无需命令行参数，所有参数在 `main.cpp` 顶部的常量中定义，修改后重新编译即可

## 2-5-1 单粒子：数据 + 更新 + 绘制

> **目标：** 定义"一个粒子"，让它沿抛物线运动，在画布上画成一个点。

**要掌握的概念：粒子 = 数据 + 更新 + 绘制**

### 第 1 步：定义粒子结构体

一个最小粒子只需要两条信息（位置 + 速度），再加一个构造函数：

```cpp
struct Particle {
    Vec3 position;   // 世界位置
    Vec3 velocity;   // 速度（每帧方向与大小）
    Particle(const Vec3& pos, const Vec3& vel);
};
```

- `position` 决定"粒子在哪"
- `velocity` 决定"每帧往哪走、走多快"

### 第 2 步：写"更新"函数——让粒子动起来

物理常识：下一帧位置 = 当前位置 + 速度 × 时间步长。

```cpp
// 更新粒子位置：pos += vel * dt
void update_particle(Particle& p, float dt);
```

- `dt`（DeltaTime）= 两帧之间经过的时间（秒）。用 1/60 ≈ 0.0166 即可
- **这是全阶段的核心思想：所有运动都是"每帧改数据"**

### 第 3 步：写"绘制"函数——把粒子画到画布

粒子在世界坐标，画面是像素。需要一个"世界 → 屏幕"的投影。最简单做法：**正交投影**（忽略远近，直接把 x/y 映射到像素）：

```cpp
// 把粒子的世界坐标投影到屏幕像素，画一个亮点
void draw_particle(Framebuffer& fb, const Particle& p);
```

映射公式（假设画布 W×H，世界坐标范围约为 [-2,2]×[-2,2]）：
```
px = (p.position.x + 2) / 4 * W      // x∈[-2,2] → [0,W]
py = (2 - p.position.y) / 4 * H      // y∈[-2,2] → [0,H]（翻转，屏幕 y 向下）
```

画法：把该像素设为白色（或淡蓝色 `[100,200,255]` 更像粒子）。

### 第 4 步：主循环——模拟 + 渲染

```
初始化：创建 1 个粒子（位置(0,0,0)，速度(1,2,0)）
每帧：
    update_particle(粒子, dt)   # 改数据
    draw_particle(画布, 粒子)   # 画出去
输出 PPM
```

因为只有一帧，你会看到粒子"飞出去"的**一个点**。为了看到轨迹，可以先在循环里输出多帧 PPM（见 2-5-6），或先把 dt 放大看单帧位置。

### 验收标准

- [x] 程序运行后输出一张 PPM，图上有一个亮点
- [x] 修改粒子的初速度，亮点的位置随之改变
- [x] 你能说清楚：粒子从出生到画出，经过了"数据 → 更新 → 绘制"哪几步

> **对应 Niagara：** `Particle` 结构体 ≈ Niagara 里每个粒子的属性（Position / Velocity）。Niagara 的"模块"本质就是"读粒子属性 → 改粒子属性"的函数，和你的 `update_particle` 一样。

## 2-5-2 粒子数组 + 发射器（Emitter）

> **目标：** 不再只有一个粒子，而是**持续生成一批粒子**。

**要掌握的概念：发射器（Emitter）= 批量生成粒子的规则**

### 第 1 步：用数组管理粒子

```cpp
std::vector<Particle> particles;   // 所有粒子的容器
```

### 第 2 步：写"发射"函数——每帧生成新粒子

```cpp
// 每帧从指定位置生成 N 个粒子，速度带随机性
void emit_particles(std::vector<Particle>& particles, const Vec3& origin, float dt);
```

要点：
- 每次 `push_back` 一个新粒子到数组末尾
- **速度要有随机性**：`velocity = (random(), random(), 0)` 范围约 [-1,1]，这样粒子才会散开成一束（没有随机性就是一条直线，不像特效）
- 发射间隔：可以每帧发射 5~10 个，控制总量别爆内存（例如超过 1000 个就跳过）

### 第 3 步：批量更新 + 批量绘制

```
每帧：
    emit_particles(...)              # ① 发新的
    for (p : particles) update_particle(p, dt)   # ② 全更新
    for (p : particles) draw_particle(fb, p)     # ③ 全绘制
输出 PPM
```

这一帧你会看到**一束粒子**（很多点，从发射点向四周散开）。

### 验收标准

- [x] 单帧画面中有多个粒子，从同一点向四面八方散开（像烟花/喷泉）
- [x] 粒子数量可调（改发射速率参数后画面变密/变疏）
- [x] 修改随机范围，粒子束的角度和长度变化明显

> **对应 Niagara：** `emit_particles` ≈ Niagara 的 **Emitter**（发射器）+ Spawn 模块。Niagara 里"发射器"就是一个持续产出粒子的单元，和你这个函数做的事一样。

## 2-5-3 生命周期：出生 → 存活 → 消亡

> **目标：** 粒子会"死"。出生时亮、渐渐变暗变透明，寿命到了就消失。

**要掌握的概念：粒子的生命周期（Lifespan）与透明度**

### 第 1 步：给粒子加寿命字段

```cpp
struct Particle {
    Vec3 position;
    Vec3 velocity;
    float life;        // 剩余寿命（秒）
    float max_life;    // 总寿命（用于算"活了多久"的比例）
};
```

- 出生时 `life = max_life`（如 3.0 秒）
- 每帧 `life -= dt`

### 第 2 步：更新函数里处理生死

```cpp
void update_particle(Particle& p, float dt);
```

- 生命值递减：`p.life -= dt;`
- **消亡 = 从数组移除**：在批量更新循环里，用"先更新、后删除"模式：

```cpp
for (auto it = particles.begin(); it != particles.end(); ) {
    if (it->life <= 0.0f) { it = particles.erase(it); }  // 死了就删
    else { update_particle(*it, dt); ++it; }
}
```

### 第 3 步：颜色随生命衰减

让粒子"越老越透明/越暗"（粒子特效的常见效果——颜色随 life 衰减）：

```
alpha = p.life / p.max_life        // 1.0（刚出生）→ 0.0（快死）
颜色 = 基色 × alpha                 // 例如 基色 [100,200,255] × alpha
```

把颜色作为 `draw_particle` 的参数传入（或用 alpha 直接缩放亮度）。

### 验收标准

- [x] 粒子出现一段时间后消失（连续多帧观察：密度先增后减，最终清空）
- [x] 粒子颜色从亮到暗渐变（单帧里"老"粒子比"新"粒子暗）
- [x] 数组不会无限增长（粒子数稳定在一定范围，而不是一直涨）

> **对应 Niagara：** `life` ≈ Niagara 的 **Particle Lifespan**；"life 归零就删" ≈ Niagara 的 **Cull / Kill 模块**。Niagara 每个粒子都有 Lifespan，到期自动销毁，和你这个逻辑一模一样。

## 2-5-4 重力 + 阻尼 + 碰撞地面

> **目标：** 粒子受重力下落、撞到地面反弹。

**要掌握的概念：力 = 每帧修改速度；碰撞 = 翻转速度分量**

### 第 1 步：加速度（重力）

每帧给速度加上一个向下的小增量，粒子就会"越落越快"（抛物线）：

```cpp
// 在 update_particle 里：
p.velocity.y -= GRAVITY * dt;   // GRAVITY ≈ 9.8，向下（y 为负方向）
p.position += p.velocity * dt;
```

### 第 2 步：阻尼（空气阻力）

阻力让速度缓慢变小，粒子束不会永远乱飞：

```cpp
p.velocity *= (1.0f - DRAG * dt);   // DRAG ≈ 0.5~1.0
```

### 第 3 步：地面碰撞反弹

假设地面在 `y = -1.8`：

```cpp
if (p.position.y < GROUND_Y) {
    p.position.y = GROUND_Y;              // 拉回地面
    p.velocity.y = -p.velocity.y * 0.6f;  // 反弹（0.6 = 弹性系数）
}
```

- `-velocity.y` 让速度从向下变向上（反弹），速度的 x/z 分量保持不变
- `× 0.6` 表示撞一次损失 40% 能量（真实粒子会越弹越低，最终停在地面）
- **反弹角度：** 粒子以镜面反射角度反弹（入射角 = 反射角），`× 0.6` 只衰减速度大小，不影响角度方向
- **物理计算简化说明：** 本阶段采用简化物理模型，适用于游戏特效场景——重力（恒定向下加速度）、阻尼（线性衰减）、平面碰撞（弹性系数）。未包含速度平方阻力、粒子间碰撞、旋转、摩擦力等，Niagara 默认碰撞模块也采用类似简化模型

### 验收标准

- [x] 粒子明显呈抛物线轨迹（先上升后下落，而非直线）
- [x] 粒子碰到地面后反弹，且越弹越低
- [x] 调大 GRAVITY 后粒子更快落地，调大 DRAG 后粒子更快静止

> **对应 Niagara：** 重力 ≈ Niagara 的 **Gravity Force** 模块；阻尼 ≈ **Drag / Air Resistance**；反弹 ≈ Niagara 的 **Collision**（Box / Plane 碰撞）。Niagara 里每个力都是一个"模块"，在每帧 tick 时改粒子速度——和你 `update_particle` 里加的那些行完全同构。

## 2-5-5 广告牌（Billboard）渲染：把点变成圆

> **目标：** 把粒子从"一个像素点"变成"一个圆形光斑"，且始终面向相机。

**要掌握的概念：粒子形状、软粒子（alpha 边缘渐变）、深度排序**

### 第 1 步：粒子有"大小"

给粒子加 `size`（半径，以像素为单位）：

```cpp
float size;   // 粒子在屏幕上的半径（像素），如 3~8
```

### 第 2 步：画圆形（而不是方块）

在 `draw_particle` 里，不要只画 1 个像素，而是遍历粒子外接矩形内所有像素，判断是否落在圆内：

```cpp
for (int dy = -size; dy <= size; ++dy)
for (int dx = -size; dx <= size; ++dx) {
    if (dx*dx + dy*dy <= size*size)      // 圆内判断（点到圆心距离² ≤ 半径²）
        fb[y+dy][x+dx] = color;          // 在圆内的像素上色
}
```

### 第 3 步：软边缘（alpha 渐变）

真实粒子边缘是柔和的（"软粒子"）。越靠圆心越亮、越靠边缘越透明：

```cpp
// 边缘柔和：distance/radius 越接近 1（边缘）越暗
float d = sqrt(dx*dx + dy*dy) / size;          // 0（中心）~ 1（边缘）
float alpha = 1.0f - d;                        // 中心 1.0 → 边缘 0.0
fb[y+dy][x+dx] = color * alpha;                // 乘到颜色上
```

### 第 4 步（进阶，不执行）：深度排序

多个粒子重叠时，后面的应被前面的挡住。本阶段不实现深度排序（粒子特效通常不需要严格遮挡关系，重叠效果反而更美观）。如果未来需要，可采用**画家算法（Painter's Algorithm）**：

1. 每帧绘制前，按粒子的世界坐标（如 y 轴或 z 轴）对所有粒子排序
2. 远的粒子先绘制，近的粒子后绘制（后绘制的覆盖先绘制的）
3. 使用 `std::sort`，比较函数为 `return a.position.y < b.position.y`（y 越小越远）
4. 时间复杂度 O(N log N)，粒子数少于 2000 时性能可接受

### 验收标准

- [x] 粒子是圆形光斑，不是方点
- [x] 边缘柔和渐变，看起来"像一团光"而不是硬边圆
- [x] 粒子大小可调（改 size 后明显变化）

> **对应 Niagara：** 圆形光斑 ≈ Niagara 的 **Sprite Renderer**（每个粒子画一个四边形，纹理=圆形渐变图）；软边缘 ≈ 粒子纹理的 alpha 通道；深度排序 ≈ Niagara 渲染器的 **Sort Mode**。**Niagara 的 Sprite 渲染器本质就是"每个粒子画一个面向相机的四边形 + 贴一张图"，你现在做的就是这个事。**

## 2-5-6 多帧动画输出（PPM 序列）

> **目标：** 连续输出多帧，观察粒子系统的动态效果。

**要掌握的概念：时间步进、帧序列**

**特效标准：** 30fps，时长 1\~2 秒 → 共 30\~60 帧 PPM 文件，避免过多文件生成

### 第 1 步：主循环改为"按帧推进"

```
dt = 1/30（30fps，每帧约 0.033 秒）
for (frame = 0; frame < TOTAL_FRAMES（30~60）; ++frame) {
    清空画布（全黑）
    emit_particles(...)
    更新所有粒子（含生死、重力、碰撞）
    绘制所有粒子
    输出 PPM：output_frame_%03d.ppm（如 output_frame_000.ppm）
}
```

输出文件名用 `snprintf` 带 3 位序号，保证按序生成。

### 第 2 步：查看动画 — PPM 序列转 GIF

PPM 不能直接播。提供一个 Python 脚本和 BAT 文件，一键将 PPM 序列合并为 GIF：

**Python 脚本 `ppm_to_gif.py`：**
- 使用 Pillow 库读取按 `output_frame_%03d.ppm` 规则命名的 PPM 文件
- 按文件名排序后合并为 GIF 动画，默认帧率 30fps
- 用法：`python ppm_to_gif.py`（自动读取当前目录的 PPM 序列）
- 首次使用需安装依赖：`pip install pillow`

**BAT 文件 `make_gif.bat`：**
- 一键执行，自动调用 `ppm_to_gif.py` 生成 GIF
- 双击运行即可，无需手动输入命令

### 验收标准

- [x] 输出 30\~60 帧 PPM 序列（30fps × 1\~2s）
- [x] 帧间粒子位置连续变化（无跳变）
- [x] 运行 `make_gif.bat` 后生成 `particle_animation.gif`，能看到完整的"喷发 → 散开 → 下落 → 反弹 → 消亡"全过程

> **对应 Niagara：** 帧循环 ≈ Niagara/UE 的 **Tick**（每帧模拟一次）；多帧输出 ≈ 引擎的帧渲染。Niagara 的粒子系统在引擎里就是"每帧被 tick 一次，读旧数据、写新数据"。

## 验收总纲

完成 6 步后，你应该能回答三个问题（这也是"理解 Niagara"的关键）：

1. **粒子系统是什么？** —— 一堆带属性的数据 + 每帧更新它们的规则 + 把数据画出来的方式
2. **粒子为什么看起来像特效？** —— 大量粒子的随机性 + 生命周期渐变 + 力的作用，组合成视觉"涌现"
