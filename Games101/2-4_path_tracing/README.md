# 2-4 路径追踪（Path Tracing）

**文件位置：** `2-4_path_tracing/`

**目标：** 实现蒙特卡洛路径追踪，用随机采样逼近渲染方程，渲染出带**间接光照**（颜色溢出）的 Cornell Box 场景——这是光线追踪的最终形态，也是 2-1 ~ 2-3 学习内容的集大成。

## 预备知识

**渲染方程：** 光线从场景表面反射出去的辐射度，等于"自己发光的能量 + 半球面所有方向反射过来的能量的积分"：

```
L(P, wo) = Le(P) + ∫ fr(P, wi, wo) · Li(P, wi) · cosθ dωi
```

- `L`：出射辐射度（像素最终看到的光）
- `Le`：自发光（只有光源非零）
- `fr`：BRDF，描述表面如何反射光（漫反射 = albedo / π）
- `Li`：从方向 wi 入射的辐射度
- `cosθ`：入射光与法线的夹角余弦（光斜射时贡献小）

**难点：** 这个积分没有解析解。路径追踪用**蒙特卡洛采样**——每次随机取一个方向 wi 来近似整个积分，发射大量光线后取平均，结果收敛到真实值。

## 新知识点

| 概念 | 说明 |
|------|------|
| **蒙特卡洛积分** | 用随机采样的平均值近似积分：采样越多，结果越接近真实值（无偏） |
| **渲染方程** | 出射光 = 自发光 + 半球入射光的积分，是全局光照的理论基础 |
| **漫反射 BRDF** | `fr = albedo / π`，把入射光按反射率（颜色）均匀散射到各个方向 |
| **半球采样** | 在法线一侧的半球面上随机生成出射方向 |
| **余弦加权采样** | `theta = acos(sqrt(r1))` 让采样密度 ∝ cosθ，与漫反射 BRDF 匹配，pdf = cosθ/π，显著降噪 |
| **俄罗斯轮盘赌（RR）** | 每次以概率 P 决定是否继续追踪，解决递归无限深度问题；结果乘 1/P 保持无偏 |
| **间接光照 / 颜色溢出** | 红光墙把红色"染"到白色地板/球上，纯光栅化做不到的效果 |
| **自发光材质** | `emitted` 字段，光源 = 普通表面 + 自发光 |
| **gamma 校正** | 输出前做 1/2.2 次幂，补偿显示器非线性，避免画面过暗 |
| **SPP（每像素采样数）** | 采样数越多噪点越少、越接近真实，代价是线性变慢 |

## 材质：如何实现、如何与计算交互

路径追踪里的"材质"就是**一组描述"光打到表面后会发生什么"的参数**。本实现只有一个最简漫反射材质，两个字段恰好对应渲染方程的两个角色：

```cpp
struct Material {
    Vec3 albedo;    // 漫反射率（颜色），范围 [0,1] → 渲染方程的 BRDF：fr = albedo / π
    Vec3 emitted;   // 自发光（仅光源非 0）      → 渲染方程的 Le
    bool is_light() const;   // emitted 任一分量 > 0 即为光源
};
```

**它与计算的交互只有两处**（都在 `path_trace` 里）：

| 步骤 | 代码 | 读取的材质字段 | 对应渲染方程 |
|------|------|--------------|-------------|
| 命中后先判断 | `if (prim.mat.is_light()) return prim.mat.emitted;` | `emitted` | `Le` |
| 弹跳后加权 | `return emitted + albedo * incoming * (PI/SURVIVAL);` | `albedo` | `fr · Li`（cosθ/π 被采样抵消） |

**理解要点：**

1. **几何归图元，能量归材质**：法线、交点位置由 `Sphere`/`Triangle` 计算；反射什么颜色、发不发光由 `Material` 决定
2. **材质不决定"往哪弹"**：弹射方向由采样函数 `cosine_sample_hemisphere` 决定；材质只决定"弹出去后贡献多少能量"
3. **框架可扩展**：将来加镜面/玻璃材质，只需换 `fr` 函数（如镜面 `fr = δ` 镜面反射）和配套的采样策略，`path_trace` 的骨架不变——这就是为什么渲染方程是全局光照的"万能框架"

## 核心算法

```
path_trace(ray, depth):
  ① 求场景最近交点 P、法线 n、材质
  ② 若命中光源：返回自发光 emitted          ← 光线走到光就结束
  ③ 俄罗斯轮盘赌：随机数 > P → 返回黑（终止）
  ④ 在法线半球上采样出射方向 wi（余弦加权）
  ⑤ 递归：incoming = path_trace(沿 wi 的新光线, depth+1)
  ⑥ 返回 emitted + albedo · incoming · π / P
```

**为什么要乘 π / P：**

1. **π**：渲染方程采样估计 = `fr · Li · cosθ / pdf(wi)`。漫反射 `fr = albedo/π`，余弦加权采样 `pdf = cosθ/π`，代入后 cosθ 与 π 全部约掉，只剩 `albedo · Li · π`
2. **1/P**：俄罗斯轮盘赌只把路径以概率 P 保留下来，把结果除以 P 才能保持期望值不变（无偏）

**为什么会有噪点：** 每次采样只能近似积分。某条路径恰好碰到光源 → 像素很亮；没碰到 → 黑色。单条路径方差极大，但 SPP 条路径平均后方差按 1/SPP 衰减，画面趋于收敛（更准确地说，误差按 1/√N 衰减：采样数 ×4，噪点减半）。

**递归 → 迭代（理解深度）：** 路径追踪的递归是**线性链式**（每个节点只有 1 个孩子，不像 BVH 遍历有 2 个孩子），因此根本不需要栈，可以改写成"沿路径累乘权重"的迭代版本，数学上完全等价：

```
color = 0, throughput = 1
循环 depth = 0..MAX_DEPTH:
  求交点；未命中 → break
  命中光源 → color += throughput · emitted; break
  RR 终止 → break
  wi = 半球采样(n)
  throughput *= albedo · π / P     # 提前把权重乘进累积变量
  发射新光线
```

迭代版的优势：不用维护函数调用栈、便于后续扩展 NEE（对光源直接采样）等算法、也是 GPU 光追（CUDA 禁递归）的标准写法。当前实现的递归深度被 `MAX_DEPTH=12` + RR 截断，最多几十层，不存在栈溢出风险。

## 采样：具体如何实现

"采样"在本实现里出现在**两个层面**：

**① 像素采样（SPP 循环）**——决定"从哪发光线"：

```cpp
for (int s = 0; s < SPP; s++) {                 // 每像素发射 SPP 条光线
    Vec3 dir = Vec3(ndc_x, -ndc_y, -1).normalized();  // 主光线穿过像素中心（确定性）
    color = color + path_trace(prims, Ray(camera_pos, dir), 0);
}
color = color / (float)SPP;                     // 平均 → 收敛到真实辐射度
```

主光线是确定的，随机性全部来自每条路径内部的弹跳。本实现没有做亚像素抖动（抗锯齿），想加只需在 `ndc_x/ndc_y` 上叠加 `(random01()-0.5)/WIDTH` 量级的随机偏移。

**② 半球方向采样（`cosine_sample_hemisphere`）**——决定"往哪弹"：

```cpp
float r1 = random01(), r2 = random01();   // ① 两个均匀随机数 [0,1)
float theta = acos(sqrt(r1));             // ② 极角：0（法线）→ π/2（切平面）
float phi   = 2.0f * PI * r2;             // ③ 方位角：绕法线均匀一圈
// ④ 以法线 n 构造正交基 (tangent, bitangent, n)
// ⑤ 球坐标→笛卡尔：local = (sinθcosφ, sinθsinφ, cosθ)
// ⑥ 基向量组合 → 世界坐标 wi
```

**随机源：** 全局 `std::mt19937`（固定种子 2026，结果可复现）+ `uniform_real_distribution<float>` 产出 [0,1) 均匀数。

**√r1 的关键作用（余弦加权的由来）：**

- 若直接取 `theta = acos(r1)`（均匀取极角），那么越靠近法线的球面带元 `dω` 越小，采样会集中在法线附近但密度不均匀，与积分里的 `cosθ` 因子不匹配，方差大
- 取 `cosθ = √r1` → `cos²θ ~ U(0,1)` → 极角的概率密度 `pdf(cosθ) = 2·cosθ`，换算到立体角上恰好是 `pdf(wi) = cosθ / π`
- 这个 pdf 与渲染方程积分的 `cosθ` 因子**成正比**，采样密度"偏爱"贡献大的方向，方差最小——这就是它与漫反射 BRDF 匹配的含义
- 推导代入：`fr·Li·cosθ / pdf(wi) = (albedo/π)·Li·cosθ / (cosθ/π) = albedo·Li`，正是代码里 `albedo * incoming * PI` 的来源（PI 来自前面的整理，见"核心算法"）

## 实现步骤

1. **Vec3 / Ray**：沿用 2-1 ~ 2-3，新增分量乘法（`albedo × incoming` 这类颜色乘法）
2. **Material 材质**：`albedo`（漫反射颜色）+ `emitted`（自发光，非光源为 0）
3. **图元**：`Sphere` + `Triangle`（MT 算法）封装成 `Primitive`，挂材质
4. **半球余弦加权采样**：球坐标 `theta = acos(sqrt(r1))`、`phi = 2π·r2`，在法线周围构造正交基后转世界坐标
5. **path_trace 递归**：见"核心算法"
6. **主循环**：逐像素发射 `SPP` 条光线（从相机穿过像素中心），累计取平均
7. **输出 PPM**：gamma 校正后量化到 [0,255]，用 `__FILE__` 定位输出路径

## 场景：Cornell Box

经典的光线追踪测试场景，专门用来展示间接光照：

```
         天花板（白）+ 面光源（自发光，发光朝下）
     ┌─────────────────────────────┐
    │ 左墙（红）                   右墙（蓝）│
    │        ●红球    ●蓝球           │
     │   ┌─────────────────────┐   │
     │   地板（白，漫反射地面）       │
     └─────────────────────────────┘
```

- 后墙 / 地板 / 天花板：白色漫反射（albedo 0.75）
- 左墙红色、右墙蓝色（让颜色溢出明显）
- 天花板中部一个自发光方形面板（`emitted = (8,8,8)`），略低于天花板避免 z-fighting
- 两个小球：红球放右半区（背靠蓝墙）、蓝球放左半区（背靠红墙），对比强烈
- 房间前方开口，相机在外面向里看

**法线朝向：** 所有墙面三角形用辅助函数自动校正——面法线与"房间中心 − 面质心"点积为负则翻转顶点顺序，保证法线指向房间内侧。

## 性能实测（Release 构建，256×256，14 个图元）

程序默认连续渲染两次，输出两张对比图，直观展示"采样数 ×4 → 噪点减半"：

| 指标 | SPP=64 | SPP=256 |
|------|--------|---------|
| 输出文件 | `output_2-4_spp64.ppm` | `output_2-4_spp256.ppm` |
| 渲染耗时 | 约 1.6 s | 约 6.4 s（正好 4 倍，线性） |
| 后墙平坦区噪声（亮度标准差） | 80.4 | 31.8（约减半，符合 1/√N） |
| 后墙平均亮度 | 187.6 | 229.1（高 SPP 更可靠采到光源） |

- 场景小，直接朴素遍历即可，无需 BVH（2-3 的加速在更大场景才有意义）
- 换更高 SPP：把 [main.cpp](main.cpp) 的 `SPP_LOW / SPP_HIGH` 改大重跑即可

## 如何调参

改 [main.cpp](main.cpp) 顶部的渲染参数区：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `WIDTH / HEIGHT` | 256 | 分辨率 |
| `SPP_LOW / SPP_HIGH` | 64 / 256 | 两次对比渲染的每像素采样数 |
| `MAX_DEPTH` | 12 | 最大递归深度（配合 RR 防止无限递归） |
| `SURVIVAL` | 0.8 | RR 继续概率，越大路径越长（间接光贡献越多） |
| 光源 `emitted` | (8,8,8) | 光源强度，画面太暗/太亮时调它 |
