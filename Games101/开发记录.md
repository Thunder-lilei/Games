## 符号约定

本记录中统一使用以下符号：

| 符号            | 含义                                                                     |
| ------------- | ---------------------------------------------------------------------- |
| `(x, y)`      | 屏幕像素坐标，原点在**左上角**，x 向右，y 向下                                            |
| `[r, g, b]`   | 颜色值，范围 \[0, 255]                                                       |
| `(u, v)`      | 纹理坐标，范围 \[0, 1]                                                        |
| `(X, Y, Z)`   | 三维空间坐标                                                                 |
| framebuffer   | 内存中的像素数组，形状 `(HEIGHT, WIDTH, 3)`，`framebuffer[y][x]` 取一个像素的 \[R, G, B] |
| depth\_buffer | 深度缓冲，形状 `(HEIGHT, WIDTH)`，每个像素存一个深度值                                   |

### 阶段环境准备

#### CMake — C++ 项目构建工具
- **作用：** 本阶段需要用 C++ 编译 `.cpp` 文件生成 `.exe`。CMake 是一个跨平台的构建系统生成器，它会根据 `CMakeLists.txt` 配置文件，自动生成 Visual Studio 的 `.sln` 解决方案文件（Windows 上），然后用 `cmake --build` 一键编译。
- **为什么需要：** 手动用 cl.exe 编译多文件项目需要写很长的命令行参数，每次新增文件都要改命令。CMake 把这些自动化了，后续添加 `.cpp` 文件只需在 `CMakeLists.txt` 加一行。
- **下载：** `https://cmake.org/files/v4.4/cmake-4.4.1-windows-x86_64.msi`（如 GitHub 访问超时，可用此链接代替 GitHub Release）
- **安装：** 选择 Windows x64 Installer 版本，安装时勾选 "Add CMake to the system PATH"。

#### Eigen — C++ 线性代数库

- **作用：** 本阶段特别是 2-3/2-4 中需要大量矩阵运算（如 4×4 变换矩阵求逆、矩阵乘法）。Eigen 是一个 header-only 的线性代数库，提供高性能的 `Matrix`、`Vector` 类型以及 `inverse()`、`transpose()`、`norm()` 等常用函数。
- **为什么需要：** 虽然 2-1 会手写 Vec3 类作为练习，但到了 BVH 和路径追踪阶段，矩阵求逆、大量向量运算会变得繁琐且容易出错。Eigen 封装好了这些基础运算，让你专注于渲染逻辑本身。课程原版作业也推荐使用 Eigen。
- **提示：** header-only 意味着不需要编译 `.lib` 或 `.dll`，只需在 `CMakeLists.txt` 中通过 `include_directories()` 指定头文件路径即可使用。
- 下载：<https://gitlab.com/libeigen/eigen/-/archive/3.4.0/eigen-3.4.0.zip>
- 解压到 `./libs/eigen-3.4.0`（相对于本文件所在目录）

#### CMake 多子项目配置

本课程后续每个阶段都是一个独立的 CMake 项目（含各自的 `CMakeLists.txt` 和 `main.cpp`）。为了让 VS 在一个文件夹下识别所有子项目，需要：

1. **根目录 `CMakeLists.txt`** — 在项目根目录 (`./`) 创建，用 `add_subdirectory()` 引入每个子目录：
   ```cmake
   cmake_minimum_required(VERSION 3.10)
   project(Games101)
   add_subdirectory(2-1_ray_sphere)
   add_subdirectory(2-2_ray_triangle)
   ```
2. **每个子目录的 `CMakeLists.txt`** — 独立的项目配置，`project()` 名称不同，目标名也不同：
   ```cmake
   project(RayTriangle)
   add_executable(ray_triangle main.cpp)
   ```
3. **VS 打开根目录** — 用 VS 的 **文件 → 打开 → 文件夹** 选择根目录，VS 自动检测 `CMakeLists.txt`
4. **启动项选择** — VS 顶部工具栏的绿色启动按钮旁的下拉菜单中，选择要运行的 `.exe` 目标
5. **新增子项目** — 只需两步：
   - 新目录下创建 `CMakeLists.txt` + `main.cpp`
   - 根 `CMakeLists.txt` 加一行 `add_subdirectory(新目录名)`
   - VS 中右键根 `CMakeLists.txt` → **配置**（或重启 VS），新目标就会出现在启动项菜单中
6. **缓存清理** — 如果 VS 的启动项菜单为空或"配置缓存"灰色不可用，可能是旧缓存干扰，删掉以下目录后重启 VS 即可恢复：
   - 根目录下的 `.vs/`（VS 本地设置）
   - 子目录下的 `build/`、`out/`（CMake 编译产物）

### 2-2 光线与三角形求交（Möller–Trumbore 算法）（已完成）

**文件位置：** `./2-2_ray_triangle\`

**目标：** 用 MT 算法求光线与三角形的交点，渲染一个四面体或简单模型。

**说明与步骤见：** [`./2-2_ray_triangle/README.md`](./2-2_ray_triangle/README.md)

#### MT 算法公式

给定三角形顶点 `A, B, C` 和光线 `O + t*D`：

```
O + t*D = (1 - u - v)*A + u*B + v*C
```

整理为矩阵形式：

```
[-D,  B-A,  C-A] * [t, u, v]^T = O - A
```

用克莱姆法则求解（设 `E1 = B-A`、`E2 = C-A`、`S = O-A`、`S1 = D×E2`、`S2 = S×E1`）：

```
t = (S2 · E2) / (S1 · E1)
u = (S1 · S)  / (S1 · E1)
v = (S2 · D)  / (S1 · E1)
```

交点条件：`t > 0, u >= 0, v >= 0, u + v <= 1`

#### 实现步骤

1. **定义 Triangle 结构体**
   - `Triangle(Vec3 v0, Vec3 v1, Vec3 v2, Vec3 color)`
   - 成员函数：`intersect(Ray ray, float& t, float& u, float& v)`
2. **定义一个四面体（4 个三角形）**
   - 四个顶点：`(0, 0.5, 0), (-0.5, -0.5, 0.5), (0.5, -0.5, 0.5), (0, -0.5, -0.5)`
   - 四个三角形面，每个面不同颜色
   - **旋转摆放：** 将四面体绕 X 轴旋转 90°（`(x, y, z) → (x, -z, y)`），让顶点 A 朝向相机（+Z）。这样相机能同时看到汇聚在 A 的三个面（红/绿/蓝），底面藏在背面；否则从相机方向只能看到一个面
   - **法线朝向：** 面法线用 `(B-A)×(C-A)` 计算后，通过"面中心指向质心"的方向校验（点积为负则翻转），保证法线始终朝外
3. **主循环**
   - 与 2-1 相同的光线生成逻辑
   - 对每条光线，遍历所有三角形，用 MT 算法求交
   - 记录最近的交点
   - 如果有交点，用重心坐标插值法线，进行 Blinn-Phong 着色
4. **深度测试**
   - 由于是逐像素发光线，每个像素取最近的交点即可，不需要 Z-Buffer

#### 验收标准

- [x] 正确渲染四面体，能看到三个面
- [x] 每个面颜色不同，有光照效果
- [x] 没有穿孔或错误的三角形

### 2-3 BVH 加速结构（已完成）

**文件位置：** `./2-3_bvh\`

**目标：** 构建 BVH（Bounding Volume Hierarchy）树，加速大量三角形/球体的求交。

**说明与步骤见：** [`./2-3_bvh/README.md`](./2-3_bvh/README.md)

**核心概念（BVH、覆盖 vs 存储、二叉 vs 空间划分树）见：** [`./核心概念.md`](./核心概念.md)

#### 要点

- **为什么加速：** 朴素遍历每条光线测所有图元，O(N)；BVH 用包围盒逐层剔除，期望 O(log N)。场景越大加速越明显
- **核心思想：** BVH 只关心每个图元的「包围盒 + 中心点」，不关心图元形状（三角形/球体均可）；根节点包围盒**覆盖**所有图元，但只有叶子节点**持有**图元
- **构建：** 选跨度最大的轴 → 按中心排序 → 中位数对半切（相对比较，非绝对规则）→ 递归，直到图元数 ≤ 阈值（本实现取 2）；每个节点独立选轴、三轴交替
- **遍历：** 测包围盒 → 命中才深入 → 叶子测图元，取最近交点
- **场景：** 1 个网格球 = 576 个三角形（经纬细分），模拟「单个模型 = 大量三角面」
- **实测：** 图元求交减少 99.9%（1.51 亿 → 19.2 万），耗时快约 80 倍（性能表见 README）

### 2-4 路径追踪（最终目标）（已完成）

**文件位置：** `./2-4_path_tracing\`

**目标：** 实现蒙特卡洛路径追踪，渲染带有间接光照的场景。

**说明与步骤见：** [`./2-4_path_tracing/README.md`](./2-4_path_tracing/README.md)

#### 核心算法

```
path_trace(ray, depth):
  if depth > max_depth:
    return black
  
  对场景求交，得到交点 P、法线 n、材质
  
  在交点 P 处，在法线方向的半球面上随机采样一个方向 wi
  
  沿 wi 发射新的光线
  
  递归计算 radiance = path_trace(new_ray, depth + 1)
  
  返回 emitted + (albedo / pi) * radiance * dot(n, wi) / pdf(wi)
```

蒙特卡洛积分的基本思想：用大量随机采样来近似积分结果，采样越多，结果越接近真实值。

#### Russian Roulette（俄罗斯轮盘赌）

解决递归无限深度的问题：

- 每次递归前，以概率 `P` 决定继续追踪，概率 `1-P` 停止
- 继续追踪的结果乘以 `1/P` 以保持无偏

```
if random() > survival_prob:
  return emitted  # 停止追踪，只返回自发光
else:
  return emitted + (albedo/pi) * radiance * dot(n, wi) / (pdf(wi) * survival_prob)
```

#### 实现步骤

1. **定义材质**
   - 漫反射材质：`albedo`（反射率）+ `emitted`（自发光颜色，非光源为 0）
   - 理想镜面反射（扩展）：给定反射方向
2. **半球面均匀采样**
   - 在法线方向上的半球面内生成随机方向
   - 用球坐标：`theta = acos(sqrt(random())), phi = 2*pi*random()`
   - 转换为笛卡尔坐标
3. **单像素多采样**
   - 每个像素发射 N 条光线（N = 32\~512）
   - 结果取平均，减少噪点
4. **主循环**
   - 逐像素发射光线，沿路径递归追踪（见"核心算法"），把采样结果累加到 framebuffer
   - 沿用 2-1~2-3 的代码组织：Vec3/Ray 等类全部写在单文件 `main.cpp` 中，配 `CMakeLists.txt` 构建，无额外头文件
5. **输出 PPM**

#### 场景建议

- 一个大的漫反射球体作为地面
- 两个小球体，一个红色、一个蓝色
- 一个面光源（自发光材质，如方形）
- 场景被包围在一个大房间内
