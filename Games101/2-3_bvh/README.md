# 2-3 BVH 加速结构

**文件位置：** `2-3_bvh/`

**目标：** 构建 BVH（Bounding Volume Hierarchy）树，加速大量三角形/球体的求交，把朴素遍历的 O(N) 降到期望 O(log N)。

## 预备知识

**光线表示：** 与 2-1/2-2 相同，`P(t) = origin + t * direction, t >= 0`。

**AABB（轴对齐包围盒）：** 由 `min` 和 `max` 两个点定义的立方体，是 BVH 节点的核心——光线先测包围盒，打不中就排除整棵子树。

**BVH 不关心图元形状：** 它只用每个图元的两个通用属性——**包围盒**（剔除用）和**中心点**（排序用）。三角形贡献顶点、球体贡献球心，最后都抽象成这两样东西参与构建。所以三角形、球体、任意图元在 BVH 眼中没有区别。

## 新知识点

| 概念 | 说明 |
|------|------|
| **AABB 与光线求交（slab 方法）** | 把盒子看成三对平行平面，逐分量求交区间取交集，`t_enter < t_exit 且 t_exit > 0` 则相交 |
| **BVH 是什么** | 二叉树加速结构，每个节点用包围盒包住其下的图元，光线先测盒、命中才深入 |
| **分割轴选择** | 图元中心在 X/Y/Z 方向跨度最大的轴；每个节点独立重选，三轴交替使用 |
| **树平衡** | 中位数分割保证左右图元数相等，树高恒为 O(log N)，避免退化成链表 |
| **叶子阈值** | 叶子最多容纳的图元数（本实现取 2），权衡节点开销与剔除效果 |
| **覆盖 vs 存储** | 根节点包围盒**覆盖**所有图元（正确性前提），但只有叶子节点**持有**图元 |
| **idx 索引数组** | 排序/切分/分组全部发生在索引数组上，图元本体永不移动，避免拷贝大对象 |
| **网格球（经纬细分）** | 把一个球面细分出 576 个三角形，模拟"单个模型 = 大量三角面"的真实场景 |
| **朴素 vs BVH 对比** | 同一场景分别用两种方式渲染，统计 AABB / 图元求交次数与耗时 |

## BVH 构建流程

以 10 个图元为例（其中混有三角形和球体）：

```
                根节点（10 个图元，包围盒 A）
               /                              \
     左节点（5 个，包围盒 B）            右节点（5 个，包围盒 C）
      /            \                      /            \
 叶(2个)         叶(3个)             叶(3个)         叶(2个)
```

1. **算包围盒**：每个图元先求自己的 AABB（三角形用顶点 min/max，球体用球心 ± 半径）
2. **根节点**：包含场景全部图元
3. **选分割轴**：收集所有图元中心，算 X/Y/Z 跨度，选跨度最大的轴
4. **排序 + 对半切**：按选定轴的中心坐标从小到大排序，从中间一分为二（排在中位数前的进左，后的进右）
5. **递归**：对左右两半重复第 3-4 步，直到图元数 ≤ 阈值 → 叶子节点
6. **向上合并**：内部节点的包围盒 = 子节点包围盒的并集，保证"打不中父包围盒必无交点"

## 网格球的实现：经纬细分

球体模型在真实引擎中就是三角网格。`make_uv_sphere()` 像地球仪经纬线一样把球面切成四边形，每个四边形再拆成 2 个三角形：

1. **参数**：24 个纬度带 × 12 个经度段 × 2 = **576 个三角形**
2. **球坐标 → 笛卡尔坐标**：`x = r·sinθ·cosφ, y = r·cosθ, z = r·sinθ·sinφ`（θ 从北极 0 到南极 π，φ 绕一圈 2π）
3. **四边形拆三角形**：取四角点 `p00/p10/p11/p01`，拆成 `(p00, p10, p11)` 和 `(p00, p11, p01)`
4. **法线朝外校验**：`(v1−v0)×(v2−v0)` 与（质心−球心）点积为负则交换 v1/v2
5. **上色**：沿经度方向 HSV 渐变（色相 = j/sectors），12 条色带均匀分布，方便观察三角面划分

## 实现要点

1. **AABB 类**：空盒构造（min 极大、max 极小）+ `expand()` 合并 + slab 方法求交（方向分量为 0 时特殊处理）
2. **BVH 结构**：`nodes` 节点池（索引代替指针）+ `idx` 索引数组 + 递归构建 `build_rec` + 递归遍历 `traverse`
3. **Primitive 统一封装**：球体/三角形的联合封装，带 `type`、`color`、`box`、`center()`、静态工厂方法
4. **主循环**：同一场景分别用 `naive_intersect`（朴素遍历）和 `bvh.traverse`（BVH）各渲染一帧，各自重置计数器，打印 AABB / 图元求交次数和耗时
5. **输出 PPM**：用 `__FILE__` 定位输出路径，PPM 固定生成在 `2-3_bvh/` 根目录

## 性能实测（Debug 构建，512×512，576 个三角形）

| 指标 | 朴素遍历 | BVH 遍历 | 说明 |
|------|---------|---------|------|
| AABB 求交次数 | 0（朴素无此步骤） | 1,251,268 | BVH 新增的廉价开销 |
| 图元求交次数 | 150,994,944 | 191,950 | 减少 99.9% |
| 渲染耗时 | 6.9 ~ 7.1 s | 0.086 ~ 0.093 s | 快约 80 倍 |

- 每次光线平均：朴素 = 576 次图元求交（=图元总数）；BVH = 约 4.8 次 AABB + 0.7 次图元求交
- "省的钱"（昂贵 MT 图元求交少 79 倍）远大于"花的钱"（便宜 AABB 求交）
